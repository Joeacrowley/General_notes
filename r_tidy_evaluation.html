3  Tidy Evaluation in R: Data Masking & Non-Standard Evaluation

3.1 Overview

This document covers data masking and tidy evaluation in R — core concepts in the tidyverse, particularly in dplyr, ggplot2, and rlang. It also flags one factual error found in the original source material.

3.2 1. Data Masking

Data masking allows you to refer to columns in a data frame directly, without the df$ prefix.

3.2.1 Base R (without masking)

df <- data.frame(age = sample(1:100, 100, replace = TRUE))
mean(df$age)
[1] 52.19

3.2.2 With data masking (dplyr)

library(tidyverse)

df %>% summarise(mean_age = mean(age))
##   mean_age
## 1    52.19

Here, age is resolved from within df — no df$ needed.

3.2.3 Why “masking”?

When dplyr evaluates age, it first looks inside the data frame. If not found there, it falls back to the global environment. This temporary priority is what “masks” the outer scope.

3.2.4 Packages that use data masking

  • dplyr: filter(), mutate(), summarise()
  • ggplot2: aes(x = age, y = score)
  • rlang: provides the underlying tools for programming with masking

3.3 2. enquo() — Capturing a Single Variable

enquo() captures a function argument as a quosure — a quoted expression bundled with its environment. This lets you delay evaluation until you’re inside a tidy context.

3.3.1 Without enquo() — Broken

my_filter <- function(data, column, value) {
  data %>% filter(column > value)  # column is not found in the data
}

my_filter(df, age, 25)
Error in `filter()`:
ℹ In argument: `column > value`.
Caused by error:
! object 'age' not found

3.3.2 With enquo() — Works

my_filter <- function(data, column, value) {
  col_quo <- enquo(column)
  data %>% filter(!!col_quo > value)
}

df <- tibble(age = c(20, 30, 40))
my_filter(df, age, 25)
# A tibble: 2 × 1
    age
  <dbl>
1    30
2    40

enquo(column) captures age as a quosure; !!col_quo unquotes it (injects it) inside filter().

3.3.3 Related functions

Function Purpose
enquo() Capture one argument as a quosure
enquos() Capture multiple arguments as quosures
quo() Manually create a quosure
!! Unquote a single quosure
!!! Splice a list of quosures
{ } Shorthand for enquo() + !! (preferred)

3.4 3. {{ }} — The Modern Shorthand

{{ var }} combines enquo() and !! in one clean step. Prefer it for single arguments in most everyday functions.

library(dplyr)

group_and_summarise <- function(data, group_col, summary_col) {
  data %>%
    group_by({{ group_col }}) %>%
    summarise(mean_val = mean({{ summary_col }}, na.rm = TRUE), .groups = "drop")
}

df <- tibble(
  gender = c("M", "F", "M", "F"),
  score  = c(85, 90, 88, 95)
)

group_and_summarise(df, gender, score)
# A tibble: 2 × 2
  gender mean_val
  <chr>     <dbl>
1 F          92.5
2 M          86.5

Limitation: {{ }} handles one variable at a time. For multiple grouping variables, use enquos() + !!! instead.

3.5 4. enquos() — Capturing Multiple Variables

enquos(...) captures any number of arguments as a list of quosures. Use !!! to splice them back into tidyverse functions.

library(dplyr)
library(rlang)

Attaching package: 'rlang'
The following objects are masked from 'package:purrr':

    %@%, flatten, flatten_chr, flatten_dbl, flatten_int, flatten_lgl,
    flatten_raw, invoke, splice
group_and_summarise_multi <- function(data, ..., summary_var) {
  group_vars   <- enquos(...)
  summary_quo  <- enquo(summary_var)

  data %>%
    group_by(!!!group_vars) %>%
    summarise(mean_val = mean(!!summary_quo, na.rm = TRUE), .groups = "drop")
}

df <- tibble(
  gender = c("M", "F", "M"),
  city   = c("A", "A", "B"),
  score  = c(85, 90, 88)
)

group_and_summarise_multi(df, gender, city, summary_var = score)
# A tibble: 3 × 3
  gender city  mean_val
  <chr>  <chr>    <dbl>
1 F      A           90
2 M      A           85
3 M      B           88

enquos() also works with a single variable, but enquo() or { } is simpler when you only need one.

3.6 5. !! and !!! Explained

3.6.1 !! — Unquote (single)

Injects one captured quosure into an expression.

summarise_one <- function(data, column) {
  col <- enquo(column)
  data %>% summarise(mean_val = mean(!!col))
}

3.6.2 !!! — Splice (multiple)

Expands a list of quosures into separate arguments — equivalent to writing them out individually.

group_multi <- function(data, ...) {
  group_vars <- enquos(...)

  data %>%
    group_by(!!!group_vars) %>%
    summarise(n = n(), .groups = "drop")
}

Analogy: if group_vars holds quo(gender) and quo(city), then !!!group_vars inside group_by() becomes group_by(gender, city).

3.7 6. String-Based Column Selection

When column names are supplied as character strings (common in Shiny or programmatically generated pipelines), use all_of() and .data[[]].

library(dplyr)

group_and_summarise_str <- function(data, group_cols, summary_col) {
  data %>%
    group_by(across(all_of(group_cols))) %>%
    summarise(mean_val = mean(.data[[summary_col]], na.rm = TRUE), .groups = "drop")
}

df <- tibble(
  gender = c("M", "F", "M", "F"),
  city   = c("A", "A", "B", "B"),
  score  = c(85, 90, 88, 95)
)

group_and_summarise_str(df, group_cols = c("gender", "city"), summary_col = "score")
# A tibble: 4 × 3
  gender city  mean_val
  <chr>  <chr>    <dbl>
1 F      A           90
2 F      B           95
3 M      A           85
4 M      B           88

3.8 7. sym() — Creating Symbols from Strings

sym() from rlang converts a character string into a symbol that can be unquoted with !! inside tidy verbs.

library(rlang)
library(dplyr)

my_summarise <- function(data, col_name) {
  sym_col <- sym(col_name)
  data %>%
    summarise(avg = mean(!!sym_col, na.rm = TRUE))
}

df <- tibble(x = c(1, 2, 3))
my_summarise(df, "x")
# A tibble: 1 × 1
    avg
  <dbl>
1     2

3.8.1 Comparison of symbol-related tools

Function Purpose Use with
sym("x") String → symbol (rlang, tidy-friendly) !!sym(...)
as.symbol("x") String → symbol (base R) Base R eval()
enquo(x) Capture argument as quosure !! in tidy verbs
{ x } Shorthand capture + unquote Inside functions

3.9 Symbols

A symbol (also called a name) is one of R’s basic building blocks.

It represents the name of an object rather than its value.

When you type age in R, you’re using a symbol — R looks it up and returns whatever value is bound to that name.

A symbol is the thing before the lookup happens.

3.9.1 Creating symbols explicitly

Normally R creates symbols implicitly, but you can create one directly from a string:

as.symbol("x")   # base R — correct
x
as.name("x")     # base R — also correct, identical to as.symbol()
x

These are base R functions. They’re useful when you have a column name as a string and need to turn it into something R can evaluate as code. You can confirm what you get back:

x <- as.symbol("age")
typeof(x)   # "symbol"
[1] "symbol"
class(x)    # "name"
[1] "name"

Note that x now holds the symbol age, not the string “age”, and not any value called age. It’s a reference waiting to be evaluated.

Why does this matter for tidy evaluation?

Inside dplyr verbs, R expects column references to be symbols, not strings. So if you have a column name stored as a string and want to use it programmatically, you need to convert it first:

df <- data.frame(age = sample(1:100, 100, replace = TRUE))

col_name <- "age"

# This won't work — dplyr sees the string "age", not the column
df %>% summarise(mean(col_name))
Warning: There was 1 warning in `summarise()`.
ℹ In argument: `mean(col_name)`.
Caused by warning in `mean.default()`:
! argument is not numeric or logical: returning NA
  mean(col_name)
1             NA
# Convert to symbol first, then unquote with !!
col_sym <- as.symbol(col_name)
df %>% summarise(mean(!!col_sym))
  mean(age)
1     48.14


3.9.2 tidyr symbols

rlang::sym() — the tidyverse version rlang::sym() does exactly the same thing as as.symbol(), but is designed to work smoothly within tidy evaluation:

rlang::sym("x")  # tidyverse — correct and preferred
x


col_sym <- sym("age")     # same result as as.symbol("age")
df %>% summarise(mean(!!col_sym, na.rm = TRUE))
  mean(age, na.rm = TRUE)
1                   48.14

Prefer sym() in tidyverse code for two reasons. First, it integrates naturally with !! and the rest of the rlang toolkit. Second, there is a plural form syms() that converts a list of strings into a list of symbols, ready to be spliced with !!!:

df <- tibble(
  gender = c("M", "F", "M", "F"),
  city   = c("A", "A", "B", "B"),
  score  = c(85, 90, 88, 95)
)

cols <- syms(c("gender", "score", "city"))

df %>% select(!!!cols)
# A tibble: 4 × 3
  gender score city 
  <chr>  <dbl> <chr>
1 M         85 A    
2 F         90 A    
3 M         88 B    
4 F         95 B

This is particularly useful when column names come from a character vector — for example, from a config file, user input, or the result of names().

3.10 8. Argument Validation: match.arg() and stop()

When writing functions that accept restricted choices or require specific inputs, validate arguments early and fail with a clear, informative error.

3.10.1 match.arg() — restricting to an allowed set

Declare the default as a vector of options and match.arg() handles both validation and the default (first element) automatically. Partial matching is also supported.

summarise_col <- function(data, col_name, fn = c("mean", "median", "sum")) {
  fn <- match.arg(fn)

  result <- switch(fn,
    mean   = mean(data[[col_name]],   na.rm = TRUE),
    median = median(data[[col_name]], na.rm = TRUE),
    sum    = sum(data[[col_name]],    na.rm = TRUE)
  )

  tibble(stat = fn, value = result)
}

summarise_col(df, "score")           # uses "mean" by default
# A tibble: 1 × 2
  stat  value
  <chr> <dbl>
1 mean   89.5
summarise_col(df, "score", "median") # explicit choice
# A tibble: 1 × 2
  stat   value
  <chr>  <dbl>
1 median    89
summarise_col(df, "score", "med")    # partial matching — also works
# A tibble: 1 × 2
  stat   value
  <chr>  <dbl>
1 median    89
summarise_col(df, "score", "non_Stat_value")
Error in match.arg(fn): 'arg' should be one of "mean", "median", "sum"

3.10.2 stop() — raising custom errors

Use stop() for conditions match.arg() can’t handle, such as checking that a column exists or is the right type. Place these checks at the top of the function so the user gets a clear message immediately rather than a cryptic error from inside a tidy verb.

summarise_col_safe <- function(data, col_name, fn = c("mean", "median", "sum")) {
  if (!col_name %in% names(data)) {
    stop("Column '", col_name, "' not found in data. ",
         "Available columns: ", paste(names(data), collapse = ", "))
  }

  if (!is.numeric(data[[col_name]])) {
    stop("Column '", col_name, "' must be numeric, but is ",
         class(data[[col_name]]), ".")
  }

  fn <- match.arg(fn)
  # ... rest of function
  
  return("met conditions")
  
}

df$city # non numeric
[1] "A" "A" "B" "B"
summarise_col_safe(df, "city")
Error in summarise_col_safe(df, "city"): Column 'city' must be numeric, but is character.
names(df) # Variable name not present
[1] "gender" "city"   "score" 
summarise_col_safe(df, "miss_var")
Error in summarise_col_safe(df, "miss_var"): Column 'miss_var' not found in data. Available columns: gender, city, score
# numeric, non-missing var
df$score
[1] 85 90 88 95
summarise_col_safe(df, "score") 
[1] "met conditions"

3.10.3 stopifnot() — compact assertions

For simple yes/no checks, stopifnot() is more concise. The named form ("message" = expression) produces readable errors and is available from R 4.0.0 onwards.

This checks that

  1. variable is a string, and length = 1,
  2. column in data,
  3. column is numeric.
summarise_col_assert <- function(data, col_name, fn = c("mean", "median", "sum")) {
  stopifnot(
    "col_name must be a single string" = is.character(col_name) && length(col_name) == 1,
    "col_name must exist in data"      = col_name %in% names(data),
    "column must be numeric"           = is.numeric(data[[col_name]])
  )

  fn <- match.arg(fn)
  # ... rest of function
  
  return("Met conditions")
}

df$city # non numeric
[1] "A" "A" "B" "B"
summarise_col_assert(df, "city")
Error in summarise_col_assert(df, "city"): column must be numeric
names(df) # Variable name not present
[1] "gender" "city"   "score" 
summarise_col_assert(df, "miss_var")
Error in summarise_col_assert(df, "miss_var"): col_name must exist in data
# Length > 1
summarise_col_assert(df, c("miss_var", "Score"))

3.10.4 rlang::abort() — tidyverse-style errors

Preferred over stop() when writing functions that integrate closely with the tidyverse. Produces structured conditions with a catchable class and better stack traces.

Need look at more.

summarise_col_tidy <- function(data, col_name, fn = c("mean", "median", "sum")) {
  if (!col_name %in% names(data)) {
    abort(
      paste0("Column '", col_name, "' not found in data."),
      class = "col_not_found_error",
      col   = col_name
    )
  }

  fn <- match.arg(fn)
  # ... rest of function
}

# Length > 1
summarise_col_tidy(df, c("miss_var", "score"))
Error in if (!col_name %in% names(data)) {: the condition has length > 1

The class argument lets callers catch specific error types with tryCatch(), which is especially useful in package development or Shiny apps.
